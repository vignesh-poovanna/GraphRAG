Onboard Computer and Flight Software

The onboard computer (OBC) is the CubeSat's central processing unit. It runs the flight software that sequences every other subsystem, schedules payload and communications activity, logs telemetry, and executes fault-handling logic when something goes wrong. Because it sits in the critical path for nearly every spacecraft function, the OBC is typically the most heavily tested piece of hardware on the bus before launch.

Processor Selection

OBC processor choice trades performance against power draw and radiation tolerance. Many CubeSat missions use commercial microcontrollers with software-level fault mitigation rather than expensive radiation-hardened parts, accepting a higher single-event-upset rate in exchange for lower cost and power consumption.

Watchdog Timers

A watchdog timer is a hardware or software counter that must be periodically reset by the flight software; if it isn't reset in time, the watchdog assumes the software has hung and forces a reset. Most OBC designs layer several watchdogs, from a fast software watchdog that catches a stuck task, up to a hardware watchdog external to the processor that can power-cycle the whole board if the processor itself becomes unresponsive.

Fault Handling and Software Updates

Flight software fault handling typically works from the same telemetry parameters used for anomaly detection elsewhere on the spacecraft: out-of-range voltages, unexpected temperature trends, or a subsystem that stops responding to commands. When a fault is detected, the OBC's response usually follows a predefined escalation, from logging and retrying at the least severe end up to forcing the spacecraft into a safe, sun-pointing mode at the most severe end. Software updates are uploaded via the uplink in stages, verified against a checksum before being written to non-volatile memory, and applied behind a rollback mechanism so a bad update can't permanently strand the spacecraft.
